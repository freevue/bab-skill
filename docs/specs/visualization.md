# Type

개선

# Why

현재 wiki에는 UI 상태표와 유닛 호출 흐름의 Mermaid 예시가 있습니다. 시각화의 관점과 근거를 구분하는 공통 기준은 없습니다.
사용자는 시나리오, 상태 전이, 코드 실행, 상호작용, 데이터, 구조, 변경 영향과 검증 범위의 예시를 확인했습니다.
이 관점을 wiki 기준으로 구성하고 spec·audit에 적용한 뒤 배포하도록 승인했습니다.
README는 같은 설명과 긴 예시가 반복되어 설치와 첫 작업을 찾기 어렵습니다.

# What

- 여덟 시각화 관점의 목적, 입력과 출력 예시를 wiki 스킬에서 제공합니다. 필요한 관점만 선택합니다.
- 그림마다 명세 기준, 코드 해석 또는 실행 관측의 근거와 범위를 적습니다. 가상 예시와 미검증을 구분합니다.
- UI 기능의 흐름에는 상태표와 Mermaid 상태도를 연결합니다. 각 전이를 담당 유닛과 기능 TC에 연결합니다.
- spec은 필요한 그림으로 빠진 결정을 확인합니다. audit은 그림·명세·구현·검증 근거를 대조합니다.
- README는 설치, 첫 작업, 시각화 활용과 업데이트를 먼저 읽을 수 있도록 정리합니다.
- 회귀 검사와 실제 스킬 적용을 확인하고 v1.0.2를 배포합니다. 현재 원격 최신 릴리스는 v1.0.1입니다.

시나리오는 특정 조건의 한 경로입니다. 상태도는 허용된 상태와 이동 조건을 보여줍니다.
실행 흐름은 함수 내부의 처리와 분기를, 상호작용은 구성 요소 간 요청과 응답을 보여줍니다.
데이터 흐름은 값의 출처와 변환을, 구조는 실행 순서와 무관한 의존을 보여줍니다.
변경 영향은 변경으로 확인할 대상을, 검증 범위는 TC별 실행 근거와 남은 항목을 보여줍니다.

# How

- [ ] wiki 정책과 기능 명세에 선택 기준, 근거 표시와 스킬별 동작을 적습니다.
- [ ] wiki 스킬의 공통 시각화 기준과 검색 기능 예시를 추가합니다. spec·audit은 기준을 링크합니다.
- [ ] UI 패턴에 상태도, 상태 유지와 비동기 경계를 추가합니다. 상태표·구성 유닛·기능 TC를 대조합니다.
- [ ] 기능 템플릿의 기존 흐름 섹션에 필요한 시각화를 선택하도록 안내합니다.
- [ ] 독립 적용에서 wiki 작성, spec의 누락 질문과 audit의 불일치·미검증 판정을 확인합니다.
- [ ] 한국어·영문 README의 반복과 추상적 표현을 줄이고 설치·업데이트 명령과 링크를 확인합니다.
- [ ] 두 manifest와 배포 문서·workflow 참조를 v1.0.2로 맞춥니다. PR과 CI 확인 후 머지·릴리스합니다.

새 스킬이나 문서 종류, 필수 frontmatter, 별도 서버와 런타임 의존성은 추가하지 않습니다.
HTML 시뮬레이터, 자동 그림 생성기와 그림의 의미를 자동 판정하는 검사기는 포함하지 않습니다.
기존 UI 명세 전체를 소급 변경하지 않습니다. 기존 문서 변경과 MIT 라이선스 파일은 읽고 보존합니다.

# Priority

P1

사용자가 이번 작업에서 구성·적용 테스트·배포를 요청했습니다.

# Wiki

- `wiki/policy/visualization.md` (신규): 관점 선택, 근거 표시와 검증 한계.
- `wiki/feature/visualization.md` (신규): wiki·spec·audit의 작성·대조 동작과 기능 TC.
- `wiki/index.md` (기존): 새 명세의 정확한 분류와 연결.
- `wiki/log.md` (기존): 확정한 변경과 배포 이력.

# Acceptance

| 번호 | 확인 | 기대 결과 |
| --- | --- | --- |
| AC-01 | 같은 검색 기능의 여덟 관점을 비교 | 각 관점의 목적과 표현이 다르고 필요한 관점만 선택 |
| AC-02 | 그림의 근거를 확인 | 명세·코드 해석·실행 관측과 가상 예시를 구분하고 읽지 않은 자료를 근거로 주장하지 않음 |
| AC-03 | 검색 UI의 상태표·상태도·유닛·TC를 대조 | 초기 진입, 성공·빈 결과·오류, 재시도·취소·늦은 응답과 새 요청이 대응 |
| AC-04 | Mermaid를 표시하지 않고 명세를 확인 | 표와 문장만으로 같은 조건·결과를 확인 |
| AC-05 | spec에 재시도·취소 조건이 빠진 요청을 전달 | 빠진 결정을 질문하고 추측을 완료 기준으로 확정하지 않음 |
| AC-06 | audit에 전이·조건 불일치와 끊어진 유닛·TC 연결을 전달 | 문제의 위치·근거·영향을 보고하고 대상 파일은 수정하지 않음 |
| AC-07 | audit에 그림은 일치하나 실행 근거가 없는 사례를 전달 | 동작은 미검증으로 보고하고 그림의 표시 성공과 구분 |
| AC-08 | 정적 화면과 단순한 작업에 적용 | 불필요한 그림과 여덟 관점의 일괄 작성을 요구하지 않음 |
| AC-09 | README와 배포 문서를 읽고 명령·링크·검사를 확인 | 반복과 추상적 홍보 문구를 줄이고 기존 동작과 설치 사실을 유지 |
| AC-10 | 회귀·명세·스킬 형식·Mermaid 표시·독립 적용을 확인 | 실제 결과와 환경을 기록하고 실패·미검증을 구분 |
| AC-11 | 원격 PR·CI·태그·릴리스와 설치 패키지를 확인 | 머지된 내용과 v1.0.2 패키지가 일치하고 공개 업데이트 경로로 읽을 수 있음 |
