# 마일스톤 로컬 검증

이슈 [#30](https://github.com/freevue/bab-skill/issues/30)의 구현과 로컬 검증 기록입니다. 실제 대상 프로젝트의 마일스톤 도입과 구분합니다.

## 범위

- 기존 스펙을 정리하는 milestone 스킬과 선택형 설정 규약을 추가합니다.
- 설정·현재 목표 읽기와 현재 묶음으로 한정한 큐를 검사합니다.
- spec·sync·issues·setup·hotfix·audit과 설치 지침의 같은 규약 참조를 확인합니다.

## 초기 구현 검증 (#30)

실행 환경은 macOS, Node.js v24.14.0입니다.

| 검사 | 결과 |
| --- | --- |
| 구현 전 관련 테스트 | 현재 범위 미지원 3건과 읽기 모듈 누락 1건으로 실패 |
| 관련 테스트 3파일 | 20건 통과. 설정, 원격 응답, 후보 선택과 가짜 gh를 사용한 CLI 통합 |
| 전체 회귀 | `node --test test/*.test.mjs`, 166건 통과 |
| wiki 구조·형상 | 명세 41페이지 통과, 실제 위반 0건과 미검증 페이지 0건 |
| 한글 문장 검사 | 새 스킬·규약·명세·검증 기록에서 위반 0건 |
| 실제 GitHub 읽기 | 미도입 상태의 큐가 진행 중 #30을 확인하고 코드 3으로 대기. 원격 변경 없음 |
| 스킬 형식 | 변경 스킬 7개의 YAML, 이름·설명·미완성 본문 검사 통과 |
| 문서 링크 | 변경 문서 25개의 로컬 링크 263개와 명시 앵커 검사 통과 |

전체 회귀 로그는 이번 작업의 임시 경로 `/private/tmp/bab-milestone-tests.log`에 보관했습니다.
정적 검사 통과는 문서 형상과 로컬 동작의 근거입니다. 스킬의 실제 목표 판단과 원격 쓰기를 증명하지 않습니다.
번들 quick_validate.py는 Python의 PyYAML 부재로 실행하지 못했습니다.
추가 설치 없이 Ruby 표준 YAML로 같은 메타데이터 제약과 미완성 본문을 검사했습니다. 번들 검사기의 실행 성공으로 보고하지 않습니다.

## 큰 응답 수정 검증 (#31)

[이슈 #31](https://github.com/freevue/bab-skill/issues/31)은 초기 166개 테스트가 큰 응답의 버퍼 실패를 검사하지 못한 문제를 다룹니다.
수정 전에는 합성 응답 150개, 1,124,831바이트에서 활성·비활성 모두 ENOBUFS와 코드 2를 재현했습니다.
이 값은 별도 읽기 전용 재현의 결과이며 실제 대규모 GitHub 저장소의 응답이 아닙니다.

새 테스트는 반복 설명을 뺀 본문 합계도 1 MiB를 넘게 구성했습니다. 단일 레코드가 1 MiB를 넘는 합성 조건도 검사합니다.
필드 축소만으로 출력 한도 아래에 들어가 테스트가 통과하는 경우와 구분합니다.

| 검사 | 결과 |
| --- | --- |
| 수정 전 회귀 | 큰 응답 5건은 ENOBUFS, 새 읽기 모듈 2건은 미구현으로 실패. 부분 실패 검사 3건은 통과 |
| 수정 후 관련 회귀 | 관련 4파일 30건 통과. 큰 응답·UTF-8·마지막 줄·부분 오류·실행 실패 포함 |
| wiki 구조·형상 | 명세 42페이지, 불일치와 미검증 페이지 0건 |
| 전체 회귀 | 176건 통과. 실패·건너뜀 없음 |
| 실제 GitHub 읽기 | 현재 진행 중 #31·#30을 읽고 코드 3으로 대기. 스트림 API 형식 확인 |
| 문서 검사 | 변경 문서 27개의 로컬 링크 274개와 명시 앵커, 한글 문장과 변경 형식 검사 통과 |

[listIssues 명세](../../wiki/unit/sync/listIssues.md)는 스트림 읽기, 필요한 필드와 전체 성공 후 반환하는 계약을 기록합니다.
수정 전 로그는 `/private/tmp/bab-31-before.log`, 관련 회귀 로그는 `/private/tmp/bab-31-related.log`입니다.
전체 회귀 로그는 `/private/tmp/bab-31-full.log`입니다. 실제 대규모 GitHub 저장소의 부하 검증과 구분합니다.

## 미검증

실제 다른 프로젝트의 기존 이슈 분류, 마일스톤 생성·재배정과 재실행은 수행하지 않았습니다.
에이전트가 목표를 나누고 spec 소속을 정하는 판단은 자동 테스트로 증명하지 않습니다.
직접 번호 sync의 에이전트 게이트와 issues의 실제 표 출력도 스킬 절차 대조 범위입니다.
실제 화면의 사람 검토, 설치한 플러그인의 로딩, 원격 CI와 릴리스는 이번 로컬 검증에 포함하지 않습니다.
