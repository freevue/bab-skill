# v1.1.0 핫픽스 검증

이 기록은 [이슈 #22](https://github.com/freevue/bab-skill/issues/22)의 스킬 적용과 패키지 검증을 구분합니다.
실제 제품의 장애 복구나 운영 배포를 실행한 기록은 아닙니다.

## 구현 범위

- [hotfix](../../plugins/bab/skills/hotfix/SKILL.md)는 진입과 검증 계획을 담당하고 기존 spec·sync·audit을 사용합니다.
- [공통 기준](../../plugins/bab/skills/sync/references/verification.md)에 영향 범위·전체 확대·실행 기록·재사용 조건을 둡니다.
- [정책](../../wiki/policy/verification-scope.md)과 [기능](../../wiki/feature/hotfix-verification.md)에 판단 기준과 FT-hotfix-01~19를 기록했습니다.
- 영문·한국어 README와 가이드, 스킬 목록과 설치 템플릿을 갱신했습니다.

## 독립 적용: 실제 실행 기록

코드·wiki·테스트 입력을 가진 격리된 Git 저장소에서 Node 24.14.0의 실제 명령을 실행했습니다.
페이지 보정 함수는 안전한 정수 검사, 빈 페이지와 범위 보정을 수행합니다. 기존 재현 TC의 입력은 JSON 파일 4개 사례입니다.
검사 명령은 실행할 때마다 명령 이름을 별도 로그에 추가합니다. 입력 JSON은 Git이 추적하지 않는 파일로 유지했습니다.

| 단계 | 동작 | `verify.mjs` 추가 실행 | 형상 검사 추가 실행 | 결과 |
| --- | --- | --- | --- | --- |
| 기준 기록 | 부모 세션에서 테스트와 형상 검사 실행 | 1회 | 1회 | 입력 4개 통과, 명세 1개·불일치 0개 |
| 첫 audit | 스킬과 원본 자료만 받은 별도 세션에서 적용 | 0회 | 0회 | 테스트 입력 3개와 형상 입력 22개의 내용 식별, 로그·환경을 대조해 재사용 |
| 입력 변경 | 같은 HEAD에서 JSON에 음수 요청 사례 추가 | 0회 | 0회 | 코드·wiki는 유지, 추적하지 않은 입력만 변경 |
| 갱신 audit | 변경한 자료로 같은 스킬을 다시 적용 | 1회 | 0회 | 테스트 입력 5개 통과, 입력이 같은 형상 검사는 재사용 |

최종 실행 로그는 테스트 2회, 형상 검사 1회입니다. 동일한 초기 입력에 대한 audit의 원본 명령 추가 실행은 0회입니다.
첫 audit은 기존 TC가 증명하지 않은 안전한 정수 경계와 입력 오류를 추가로 확인했습니다. 정상 10개·실패 20개가 통과했습니다.
이 추가 검사는 기존 명령의 반복과 구분했습니다. 갱신 audit은 이 검사와 문장 검사도 불필요하게 다시 실행하지 않았습니다.
추가로 부모 세션에서 입력을 읽지 않는 작업 메모만 커밋했습니다. HEAD는 바뀌었지만 관련 입력 6개의 내용은 같았고 검사 추가 실행은 0회였습니다.
두 audit 모두 명세·코드의 의미를 대조했습니다. 이슈·PR·필수 CI는 가상 자료에 없어 미검증으로 보고했습니다.

별도 세션의 기본 Node 버전은 원본과 달랐습니다. 원본 Node 실행 파일과 버전을 확인했고 같은 조건으로 재사용·재실행했습니다.
커밋 해시나 파일 수정 시각만으로 동일성을 판단하지 않았습니다. 검사 도구와 그 도우미도 형상 검사의 입력에 포함했습니다.

## 독립 적용: 범위 선택

다른 별도 세션에 실제 스킬과 14개 가상 요청의 원본 자료만 전달했습니다.
구현과 원격 변경은 허용하지 않았고 검증 계획만 작성했습니다. 다음은 계획의 판단 결과이며 테스트 실행 결과가 아닙니다.

| 사례 | 제공한 변경 | 관측한 계획 |
| --- | --- | --- |
| A | 내부 분기와 유지되는 목록 계약 | 재현·관련 유닛·목록 검사 선택, 무관한 전체 검사 제외 사유 기록 |
| B | 목록·API·화면으로 영향 전파 | 사용처 한 단계에서 멈추지 않고 화면 경계까지 추적 |
| C | 한 줄·P0의 공개 응답 필드 변경 | 전체 검증으로 확대 |
| D | 여러 기능의 전역 캐시 키 변경 | 전체 검증으로 확대 |
| E | DB 스키마·저장 형식 변경 | 전체 검증으로 확대 |
| F | 인가 규칙 변경 | 전체 검증으로 확대 |
| G | 런타임 의존성과 lock 해석 변경 | 전체 검증으로 확대 |
| H | 빌드·컴파일러·테스트 설정 변경 | 전체 검증으로 확대 |
| I | 동적 사용처와 영향 경계 불명 | 전체 검증과 미검증 경계 구분 |
| J | 계획 밖의 다른 기능 실패 | 확대와 중단 조건을 구분하고 범위 밖 수정 금지 |
| K | 전체 린트만 가능한 국소 수정 | 전체 린트와 부분 테스트를 구분, 설정 우회 없음 |
| L | 전체 테스트가 필수 PR CI의 담당 | 관련 로컬 검사와 CI를 분담하고 로컬 전체 추가 요구 없음 |
| M | 일반 sync 요청 | 핫픽스로 전환하지 않고 기존 전체 검증 범위 유지 |
| N | 재현·기대 동작·확정 이슈 없음 | 필요한 질문과 spec 정리를 먼저 계획, 미승인 원격 변경 없음 |

제공되지 않은 명령 문자열과 기대 동작은 만들지 않았습니다. 모든 검사는 실행 예정으로 구분했습니다.

## 정적·회귀 검사

| 검사 | 결과 |
| --- | --- |
| Node 24.14.0에서 `node --test test/*.test.mjs` | 기존 회귀 73개 통과, 실패 0개 |
| `drift-check.mjs . --json` | 명세 10개, 불일치 0개 |
| skill-creator의 `quick_validate.py` | hotfix·audit 스킬 유효 |
| Claude Code `plugin validate plugins/bab` | 플러그인 manifest 유효 |
| Claude Code 로컬 플러그인 로더 | 같은 패키지의 스킬 9개 로드 확인 |
| 문장·로컬 링크·앵커 | 변경 문서 검사 통과. 세부 개수와 최종 CI는 PR에 기록 |
| 두 마켓플레이스 | 같은 `plugins/bab/`과 같은 버전의 manifest를 참조 |

sync의 기존 `disable-model-invocation` 필드는 범용 quick_validate가 지원하지 않아 해당 검사는 실패했습니다.
이 필드는 기존 버전부터 있으며 이번 변경에서 유지했습니다. Claude Code의 실제 로더는 이 필드를 포함해 9개 스킬을 읽었습니다.

회귀 테스트와 형상 검사는 스킬의 판단을 직접 증명하지 않습니다. 위 독립 적용의 관측 결과와 구분합니다.
배포 시 PR·main·태그와 공개 패키지의 일치를 별도로 확인하고 릴리스 노트에 기록합니다.

## 한계

Claude Code는 플러그인 로드와 manifest 검사를 확인했습니다. 로그인되지 않아 모델이 실제 스킬을 수행하는 세션은 시작하지 못했습니다.
별도 Codex 에이전트에서는 스킬을 읽고 위 범위 선택과 실제 audit을 적용했습니다.
실제 프로젝트 전체의 속도 개선, 운영 DB·네트워크·현재 화면의 결과 재사용과 모든 입력 조합은 미검증입니다.
새 테스트 실행기나 영구 캐시는 추가하지 않았습니다. 입력 동일성과 영향 경계는 현재 도구와 근거를 읽는 에이전트가 판단합니다.
