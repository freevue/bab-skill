# bab v3.0.0

v3.0.0은 공개 스킬 이름을 변경하는 주 버전입니다. 아래 갱신 절차는 태그 공개 후에 적용합니다.

## 변경 사항

- 독립 `bab:simple-english` 스킬을 제거합니다.
- 스펙과 wiki의 [한글 작성 규칙](../../plugins/bab/skills/wiki/references/writing-rules.md)에 ASD-STE100에서 차용한 원칙과 한국어 적용 범위를 기록합니다. 공식 영문 규격의 준수 판정은 하지 않습니다.
- spec·wiki는 작성 직후 용어, 조건과 결과를 확인합니다. sync·audit은 합의한 의미의 보존과 기계 검사의 한계를 대조합니다.
- `prose-check.mjs`는 6문장 초과 문단을 보고합니다. 코드 블록, 제목, 표와 목록은 문단 길이에서 제외합니다.
- PR의 문서 품질 리포트는 기준 커밋과 변경본을 같은 검사기로 대조합니다. 새 위반만 Actions 요약에 표시하며 문장 위반은 보고 전용입니다. 검사 실행 오류는 실패로 남깁니다.
- 내용이 같은 문서는 문장 검사를 생략합니다. 코드 울타리 판독은 줄을 한 번 순회해 긴 문서의 반복 복사를 없앴습니다.

## 호환성과 갱신

`bab:simple-english`를 직접 호출하던 작업은 갱신 후 같은 이름으로 실행할 수 없습니다. 한국어 스펙과 wiki는 기존 spec·wiki·sync·audit 흐름에서 한글 작성 규칙을 사용합니다.
스킬 이름은 공개 계약이므로 [버전 규칙](../guide.ko.md#호환성과-버전)에 따라 주 버전을 올립니다. 이슈 상태, wiki 종류와 필수 섹션, 드리프트 검사 상태 코드는 유지합니다.

태그와 릴리스가 공개된 뒤 플러그인과 대상 저장소의 GitHub Actions를 각각 v3.0.0으로 갱신합니다. 대상 저장소의 `uses`와 `bab-ref`를 함께 바꾸고 [업데이트 절차](../guide.ko.md#플러그인과-ci-업데이트)를 따릅니다.
setup은 기존 지침과 템플릿을 덮어쓰지 않습니다. dry-run으로 차이를 확인한 뒤 필요한 내용만 반영합니다.

## 검증 범위

macOS, Node.js v24.14.0의 로컬 후보에서 다음을 확인했습니다.

| 검사 | 결과 |
| --- | --- |
| 전체 회귀 | `node --test test/*.test.mjs`: 187건 통과, 실패·건너뜀 없음 |
| 버전 일치 | 전체 회귀에서 두 manifest와 저장소·setup workflow의 `v3.0.0` 참조 일치 확인 |
| wiki 구조·형상 | `wiki-check` 위반 없음. `drift-check` 45페이지 `pass`, 위반·미검증 0건 |
| PR 문서 리포트 | 기준선·새 위반·이동·중복·심볼릭 링크·오류와 동일 파일 생략의 로컬 테스트 7건 통과. 실제 GitHub Actions 실행은 미검증 |
| 한글 문장 | 새 정책·작성 규칙·릴리스 문서와 README에서 위반 없음. 기존 문서 15곳의 긴 문단은 변경 전에도 동일하게 보고됨 |
| 로컬 링크 | 변경 문서의 로컬 링크 224개 확인, 누락 0개 |
| 변경 형식 | `git diff --check` 통과 |

기존 문서 전체의 문장 재작성은 이번 범위가 아닙니다. 새 문단 검사가 기존 파일에서 보고하는 항목은 변경 전 내용과 대조해 구분했습니다.

## 게시 전 확인

1. [이슈 #33](https://github.com/freevue/bab-skill/issues/33), [#34](https://github.com/freevue/bab-skill/issues/34)와 후보 diff를 대조하고 로컬 검증 결과를 기록합니다.
2. 후보 커밋에 `v3.0.0` 태그를 두고 원격에 게시합니다. 저장소의 PR workflow가 이 태그의 재사용 workflow를 참조하므로 태그 공개 전 PR CI 성공을 주장하지 않습니다.
3. 같은 후보의 원격 CI와 PR 결과를 확인합니다. 병합 커밋과 태그 커밋이 다르면 내용도 대조합니다.
4. GitHub Release, 플러그인 갱신과 새 대화에서의 로딩을 각각 확인합니다.
