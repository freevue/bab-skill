# bab v2.0.0 릴리스 준비

상태: 검토용 업데이트 준비. 태그·GitHub 릴리스는 게시하지 않았습니다.
현재 공개 안정 버전은 v1.1.0입니다.
근거 이슈는 [#24](https://github.com/freevue/bab-skill/issues/24)입니다.

## 이번 버전의 범위

Rust 명세를 읽지 못한 것을 실제 선언 누락으로 오인하던 문제를 수정합니다.
Rust의 fn·struct·매개변수·반환형·필드를 자동 대조하는 파서는 추가하지 않았습니다.

| 대상 | 이번 버전의 자동 검사 |
| --- | --- |
| JavaScript·TypeScript | 기존 선언 문법 범위에서 형상을 대조합니다 |
| Rust | 명세를 보관하고 미지원·미검증으로 보고합니다 |
| 미등록 확장자·무확장자 | 판정 불가로 보고합니다 |
| 모든 언어 | 문서 구조·필수 내용·링크·파일 존재 검사를 유지합니다 |

따라서 이 버전을 Rust와 TypeScript의 두 언어 자동 대조 지원으로 안내하지 않습니다.

## 변경 내용

- code 경로의 확장자로 언어를 판정하고 코드 블록 표기의 별칭·대소문자·공백을 정규화합니다.
- 표기 누락·충돌·같은 페이지의 언어 혼합을 구분합니다.
- 실제 위반은 `items`, 미검증은 `unverified`로 분리합니다.
- `checkedPageCount`, `unverifiedPageCount`, `checkedTargets`로 범위와 이슈 해소 근거를 기록합니다.
- 입력·실행 오류는 코드 2, 미검증은 코드 4로 보고합니다.
- 기존부터 있던 미검증도 PR에서 성공으로 처리하지 않습니다.
- 미검증·검사 근거 없는 대상의 기존 이슈를 해소·종료하지 않습니다.
- wiki·sync·audit와 두 언어의 가이드를 같은 계약으로 맞췄습니다.

## 주 버전을 올리는 이유

검사 상태 코드는 기존 [공개 계약](../guide.ko.md#호환성과-버전)입니다.
기존 소비자가 종료 코드 0~3만 처리하면 새 코드 4를 구분하지 못합니다.
새 소비자는 필수 필드가 없는 이전 JSON을 입력 오류로 거부합니다.
이 두 변경은 호환되지 않으므로 v1.1.1이나 v1.2.0으로 배포하지 않습니다.

## 전환 절차

v2.0.0 태그와 릴리스가 게시된 뒤에 다음 절차를 적용합니다.

1. 플러그인과 CI를 같은 버전으로 갱신합니다. 두 manifest의 버전은 2.0.0입니다.
2. 대상 workflow의 `uses`와 `bab-ref`를 모두 v2.0.0으로 맞춥니다.
3. 기존 JSON은 새 검사기로 다시 생성합니다. 필드가 없다고 빈 미검증으로 간주하지 않습니다.
4. 외부 소비자도 코드 4를 미검증으로, 코드 2를 입력·실행 오류로 처리합니다.
5. 코드 4나 `status: incomplete`를 검증 성공·완료·이슈 해소의 근거로 사용하지 않습니다.
6. 기존 setup은 설치 파일을 덮어쓰지 않으므로 dry-run의 차이를 확인하고 갱신합니다.

게시 후의 workflow 참조는 다음과 같습니다.

```yaml
jobs:
  guard:
    uses: freevue/bab-skill/.github/workflows/bab-guard.yml@v2.0.0
    with:
      bab-ref: v2.0.0
```

준비 단계에서 저장소 자체의 `.github/workflows/bab.yml`은 게시된 v1.1.0을 유지합니다.
존재하지 않는 태그를 PR 검사에서 먼저 참조하지 않기 위한 설정입니다.
새 setup 템플릿은 게시할 v2.0.0을 가리킵니다.

## 검증과 게시 전 조건

[구현 검증 기록](../verification/drift-language.md)에 실행 근거가 있습니다.

| 항목 | 상태 |
| --- | --- |
| 두 manifest의 버전 일치 | 2.0.0으로 준비 |
| 새 setup 템플릿의 uses·bab-ref | v2.0.0으로 준비 |
| 구현 전체 회귀 | 109개 통과 |
| 버전 변경 후 전체 회귀 | 109개 통과, 실패·건너뜀 0개 |
| 독립 표본의 setup 설치 | 플러그인 버전·생성 workflow가 v2.0.0으로 일치 |
| 문장·wiki 구조·공백 | 위반 없음 |
| 전체 형상 검사 | 실제 위반 0건, 기존 기능 2페이지 미검증, 코드 4 |
| 원격 PR·Node 20 CI | 미실행 |
| v2.0.0 태그·공개 패키지·릴리스 | 미게시 |

기존 hotfix-verification과 visualization 기능의 code 경로는 Markdown 스킬 문서입니다.
확정한 확장자 규칙에 따라 두 페이지는 `unknown-language`로 남습니다.
전체 명세 29페이지 중 27페이지를 검사했고 2페이지는 미검증입니다.
이 문서 기반 기능의 판정 범위는 별도 합의가 필요합니다.
이 조건을 해소하고 원격 CI를 확인하기 전에는 게시 완료로 판단하지 않습니다.

## 게시 순서

1. 위의 미검증 판정 범위를 합의하고 필요한 명세·검사를 보완합니다.
2. 현재 변경의 PR과 해당 커밋의 CI를 검증합니다.
3. 머지할 커밋과 최종 패키지 내용을 확인합니다.
4. 게시 요청 범위에서 v2.0.0 태그와 릴리스를 만듭니다.
5. 태그가 존재하면 저장소 자체의 CI 참조도 v2.0.0으로 전환합니다.
6. 공개 설치 경로로 두 manifest·스킬·workflow가 같은 태그의 내용인지 확인합니다.

버전업 준비와 릴리스 게시를 구분합니다.
이번 작업에서는 스펙의 Rust 자동 대조 범위를 넓히지 않았습니다.
