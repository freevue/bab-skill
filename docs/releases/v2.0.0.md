# bab v2.0.0

기존 JavaScript·TypeScript 검사에 Rust 함수·구조체의 실제 형상 대조를 추가했습니다.
근거는 [#24](https://github.com/freevue/bab-skill/issues/24)와 [PR #25](https://github.com/freevue/bab-skill/pull/25)입니다.

## Rust 지원 범위

| 대상 | 자동 검사 |
| --- | --- |
| 최상위 공개 fn | 선언, 매개변수·반환형과 문서 표를 대조합니다 |
| 일반·필드 없는 struct | 선언, 필드 타입·공개 범위와 문서 표를 대조합니다 |
| 제네릭·수명·where·함수 한정자 | 지원 선언에서 보존하고 대조합니다 |
| 주석·문자·문자열·raw string | 가짜 선언을 제외합니다. 중첩 블록 주석도 구분합니다 |
| 기능 구성 | 이름으로 식별하는 직접 호출과 단순 use 별칭을 대조합니다 |
| 지원 밖 문법 | unsupported-syntax와 미검증 코드 4로 보고합니다 |

Rust 컴파일러를 설치하지 않아도 검사할 수 있습니다.
impl·trait·enum·type·mod·튜플 구조체·매크로 선언·조건부 속성·패턴 매개변수는 지원 밖입니다.
해당 문법이 있는 파일의 관련 페이지는 미검증으로 보호합니다.
Rust 기능의 메서드·변수·매개변수 호출과 복잡한 use 관계도 미검증입니다.
지원 속성은 doc·derive·repr입니다. 속성 실행과 매크로 확장은 검사하지 않습니다.
정확한 범위는 [Rust 계약](../../wiki/feature/drift-language-support.md#rust-지원-범위)을 따릅니다.
이 검사는 Rust 컴파일·타입 검사나 동작 검증을 대신하지 않습니다.

## 보고서와 CI 변경

- 확장자로 언어를 판정합니다. 코드 블록의 별칭·대소문자·공백을 정규화합니다.
- 실제 위반은 items, 미검증은 unverified로 분리합니다.
- checkedPageCount·unverifiedPageCount·checkedTargets로 검사 범위를 기록합니다.
- 입력·실행 오류는 코드 2, 미검증은 코드 4로 보고합니다.
- 기존 미검증도 PR에서 성공으로 처리하지 않습니다.
- 미검증·검사 근거 없는 대상의 기존 드리프트 이슈를 보존합니다.
- 문서 절차만 있는 feature는 code: []와 구성 스킬 링크를 사용합니다.

기존 hotfix-verification·visualization의 Markdown code 지정도 이 규칙으로 바로잡았습니다.
구성 스킬 링크와 TC를 유지합니다. 문서 검사가 스킬 실행 성공을 뜻하지 않습니다.

## 주 버전을 올리는 이유

검사 상태 코드는 기존 [공개 계약](../guide.ko.md#호환성과-버전)입니다.
종료 코드 4를 추가했고, 필수 필드가 없는 이전 JSON은 입력 오류로 거부합니다.
이 두 변경은 호환되지 않으므로 현행 버전 정책에 따라 v2.0.0으로 배포합니다.
Rust 추가만으로 주 버전을 올리는 것은 아닙니다.

## 전환 절차

1. 플러그인과 CI를 함께 v2.0.0으로 갱신합니다.
2. workflow의 uses와 bab-ref를 모두 v2.0.0으로 맞춥니다.
3. 기존 JSON은 새 검사기로 다시 생성합니다.
4. 외부 소비자도 코드 4를 미검증으로, 코드 2를 입력·실행 오류로 처리합니다.
5. 미검증을 검증 성공·완료·이슈 해소의 근거로 사용하지 않습니다.
6. 기존 setup은 파일을 덮어쓰지 않으므로 dry-run의 차이를 확인하고 갱신합니다.

```yaml
jobs:
  guard:
    uses: freevue/bab-skill/.github/workflows/bab-guard.yml@v2.0.0
    with:
      bab-ref: v2.0.0
```

두 manifest의 버전과 새 setup 템플릿은 v2.0.0입니다.
이 저장소의 CI 참조는 태그가 존재한 뒤 별도 PR에서 전환합니다.
릴리스 태그 안의 기존 CI 참조는 이전 공개 버전입니다. 배포되는 새 setup 템플릿에는 영향을 주지 않습니다.
