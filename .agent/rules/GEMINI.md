# bab 프로젝트 공통 규칙

이 문서는 bab 저장소의 공통 지침입니다. 두 에이전트의 진입 파일에서 이 문서를 참조합니다.

## 코드 컨벤션

- 변경 범위를 작게 유지합니다. 기존 코드, 표준 라이브러리, 이미 쓰는 의존성 순서로 재사용할 방법을 찾습니다. 현재 요구를 해결하는 가장 단순한 구조를 고릅니다(Ponytail, YAGNI).
- 단순화하더라도 입력 검증, 데이터 손실 방지, 권한 확인, 접근성은 유지합니다.
- 문서와 주석은 한국어로 씁니다. 코드 식별자, 예약어, 널리 쓰는 기술 용어는 영어로 표기할 수 있습니다.
- bab의 기존 Node.js 스크립트는 `.mjs` 형식을 유지합니다.

### TypeScript

새 프로젝트에서 언어를 선택할 수 있다면 TypeScript를 기본으로 검토합니다. 다음 규칙은 TypeScript 소스에 적용합니다.

- `any`를 사용하지 않습니다. 타입을 모르는 외부 값은 `unknown`으로 받은 뒤 검증합니다.
- 파일은 150줄 이하로 유지합니다. 넘으면 관련 책임을 기준으로 나눕니다.
- 한 글자 식별자를 쓰지 않습니다. 변수·상수·매개변수·함수는 `camelCase`, 클래스는 `PascalCase`를 씁니다. 예를 들어 `e` 대신 `event`를 씁니다.
- 문자열을 조합할 때는 템플릿 리터럴을 사용합니다.
- 단일 파일은 Named Export를 사용합니다. 폴더의 공개 export는 `index.ts`에 모읍니다. 폴더 내부에서는 필요한 파일을 직접 참조합니다.
- 함수형 스타일을 따릅니다. Early Return, 불변성, 커링을 우선합니다.
- Tree Shaking을 고려합니다. 모듈을 불러올 때 부수 효과가 없는 패키지에만 `package.json`의 `sideEffects: false`를 설정합니다.

### 기술별 선택 규칙

아래 규칙은 해당 기술을 사용하는 프로젝트가 채택할 때 적용합니다.

| 기술 | 채택할 수 있는 규칙 |
| --- | --- |
| 함수형 로직·`@fxts/core` | 대량 데이터를 한꺼번에 만들 필요가 없으면 제너레이터로 순회합니다. 이미 `@fxts/core`를 사용하는 경우 필요한 변환을 조합합니다. |
| React | Props는 `type`으로 정의합니다. `React.FC`에서 Props를 구조 분해하지 않고, `onClick`처럼 이름을 붙인 핸들러를 JSX 밖에 둡니다. 기본 UI와 서비스 로직을 나누고, 상태는 컴포넌트당 3개를 넘기기 전에 책임을 분리합니다. |
| NestJS | 도메인별 모듈을 기본으로 검토하고 컨트롤러·서비스·저장소의 책임을 나눕니다. DTO에서 입력을 검증하고 공통 예외 필터로 오류 응답을 맞춥니다. 규모와 요구에 따라 Hexagonal Lite나 CQRS를 선택합니다. |

## bab 작업 규칙

- 스펙은 GitHub 이슈, 명세는 [`wiki/index.md`](../../wiki/index.md), 구현 기록은 PR입니다.
- 코드는 wiki에 맞춥니다. wiki와 코드가 다르면 코드를 고칩니다.
- 이슈는 스펙을 관리하는 투두, PR은 그 작업을 올리는 곳입니다. 최종 검증은 wiki 문서의 완결성입니다. 문서가 함수 이름과 매개변수 하나까지 빠짐없이 적혀 있어야 합니다.
- 확정, 클로즈, 캔슬은 사람이 해도 되고 에이전트가 해도 됩니다. 누가 하든 `/bab:spec` 규칙대로 근거를 코멘트로 남깁니다.
- `status:decided` 이슈만 작업합니다. 작업은 `/bab:sync <이슈 번호>`로 진행합니다.
- 함수 JSDoc에는 한 줄 요약과 wiki 유닛 경로만 적습니다.

### 최종 브리핑

작업을 마치고 사용자에게 보고할 때 아래 순서를 따릅니다. 해당 없는 블록은 뺍니다.

| 순서 | 블록 | 내용 |
| --- | --- | --- |
| 1 | 결론 | 지금 무엇이 사실인지 1~2문장으로 적습니다. 실패나 미검증이 있으면 첫 문장에 적습니다 |
| 2 | 변경 | `파일 \| 무엇을` 표로 적습니다. 파일은 링크로 답니다 |
| 3 | 검증 | 실행한 검사와 결과를 적습니다. 실행하지 못한 것은 `미검증`으로 적습니다 |
| 4 | 남은 일·주의 | 목록으로 적습니다 |
| 5 | 결정할 것 | 사용자가 답해야 할 질문을 맨 끝에 둡니다 |

- 한 문장에는 한 가지 생각만 담습니다.
- 3개 이상을 비교하거나 나열하면 표로 씁니다.
- 경로와 식별자는 백틱으로 감쌉니다.
- 명령은 언어를 지정한 코드 블록에 하나씩 넣습니다.
- 추측은 `추측`이라고 표시합니다.
- 장식용 이모지와 같은 내용의 반복은 쓰지 않습니다.
- 이슈와 PR은 전체 URL로 링크합니다.
- `/bab:sync` 보고에는 이슈·PR 링크, 변경된 wiki 페이지, TC 결과 표를 반드시 넣습니다.

```markdown
페이지 범위 보정을 구현했고 PR을 열었습니다. 머지는 아직입니다.

| 파일 | 무엇을 |
| --- | --- |
| `wiki/unit/page/clampPage.md` | 시그니처와 TC 3개 추가 |
| `src/page/clampPage.ts` | wiki대로 구현 |

| TC | 결과 |
| --- | --- |
| UT-clampPage-01~03 | 통과 |

- 이슈: https://github.com/owner/repo/issues/12
- PR: https://github.com/owner/repo/pull/20

남은 일: 목록 화면 E2E 테스트는 미검증입니다.
```
