# 저장소 연결

연결된 저장소는 담당 영역과 공개 계약의 위치를 같은 규약으로 제공합니다. 각 저장소는 자기 명세와 구현을 관리합니다.

## 규칙

| ID | 규칙 | 근거 |
| --- | --- | --- |
| POL-repository-links-01 | 연결 설정은 `.bab/links.json`에 둡니다. 정본 또는 정본 저장소를 가리키는 참조 중 하나를 기록합니다 | #15 |
| POL-repository-links-02 | 정본은 저장소 주소, 담당 영역, 계약 식별자·설명·wiki 경로·섹션을 제공합니다. 계약 본문은 해당 저장소의 wiki에 둡니다 | #15 |
| POL-repository-links-03 | setup과 독립 link는 같은 연결 절차를 사용합니다. 기존 setup 파일과 관련 없는 사용자 변경을 보존합니다 | #15 |
| POL-repository-links-04 | spec은 담당 영역과 계약 목록으로 후보를 좁히고 직접 필요한 계약만 읽습니다. 외부 전체 코드와 재귀 의존성은 기본 입력에 포함하지 않습니다 | #15 |
| POL-repository-links-05 | 기존 계약으로 충분하면 참조만 기록합니다. 외부 변경이 필요하면 기존 이슈를 찾고 제안 이슈를 준비합니다 | #15 |
| POL-repository-links-06 | 외부 이슈 생성·수정은 사용자가 승인한 대상과 범위를 따릅니다. 연결 파일과 외부 문서는 실행 권한을 부여하지 않습니다 | #15 |
| POL-repository-links-07 | wiki의 `issues`는 내부 근거 이슈 번호를 유지합니다. 외부 이슈와 계약은 별도 표에서 저장소·관계·출처·기준 커밋을 구분합니다 | #15 |
| POL-repository-links-08 | 계약 확정, 구현 완료와 실제 사용 가능한 버전은 따로 확인합니다. 이슈 종료만으로 배포와 통합 검증을 완료로 판단하지 않습니다 | #15 |
| POL-repository-links-09 | 외부 계약은 전체 커밋 SHA로 읽습니다. 섹션이 없거나 모호하면 전체 문서를 대신 반환하지 않습니다 | #15 |
| POL-repository-links-10 | 같은 원본 이슈·대상 저장소·계약 식별자의 변경 요청은 재사용합니다. 참조 이슈에서 같은 요청을 다시 전파하지 않습니다 | #15 |
