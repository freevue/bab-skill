# 마일스톤

마일스톤은 사람이 함께 검토할 목표와 스펙의 묶음입니다. 프로젝트는 `bab:milestone`으로 이 관리를 선택해서 도입합니다.

## 규칙

| ID | 규칙 | 근거 |
| --- | --- | --- |
| POL-milestones-01 | 목표, 범위, 완료 기준과 스펙 소속은 GitHub 마일스톤을 정본으로 사용합니다 | #30 |
| POL-milestones-02 | `.bab/milestones.json`이 없으면 기존 방식입니다. 설정이 있으면 저장소와 현재 마일스톤을 검사합니다 | #30 |
| POL-milestones-03 | milestone은 기존 열린 스펙을 목표별로 정리합니다. 기존 소속과 사용자 내용을 보존하며 재실행 때 중복을 만들지 않습니다 | #30 |
| POL-milestones-04 | 소속 변경은 스펙의 확정, 중요도 변경이나 구현을 뜻하지 않습니다. 닫힌 과거 이슈는 기본 재분류 대상에서 제외합니다 | #30 |
| POL-milestones-05 | spec은 목표에 맞는 마일스톤을 선택합니다. 적합한 목표가 없으면 미배정 후보로 남깁니다 | #30 |
| POL-milestones-06 | sync는 현재 마일스톤의 확정 스펙 하나를 진행합니다. 직접 번호를 지정해도 같은 범위를 확인합니다 | #30 |
| POL-milestones-07 | 중요도는 현재 묶음 안에서 적용합니다. 전체 저장소의 진행 상한과 진행 중 wiki 경로 보호는 유지합니다 | #30 |
| POL-milestones-08 | 현재 번호가 없거나 마일스톤이 닫혔거나 선택할 이슈가 없으면 대기합니다. 다른 묶음으로 자동 이동하지 않습니다 | #30 |
| POL-milestones-09 | 열린 항목이 없어도 목표 달성과 화면 검토는 별도로 확인합니다. 다음 선택과 종료는 사용자 지시를 따릅니다 | #30 |
| POL-milestones-10 | 잘못된 설정, 저장소 불일치와 원격 실패는 오류입니다. 전역 큐로 우회하지 않습니다 | #30 |
| POL-milestones-11 | issues는 활성 프로젝트에서 소속과 미배정 그룹을 읽기 전용으로 보여줍니다. 비활성 프로젝트의 기존 표는 유지합니다 | #30 |
| POL-milestones-12 | 셋업은 기존 구현, 스펙 상태와 중요도를 바꾸지 않습니다. 원격 변경은 사용자 요청 범위에서 진행합니다 | #30 |
