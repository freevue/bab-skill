# 시각화

시각화는 명세와 동작을 이해하고 대조하는 수단입니다. 필요한 관점을 골라 기존 명세 안에 작성합니다.

## 규칙

| ID | 규칙 | 근거 |
| --- | --- | --- |
| POL-visualization-01 | 시나리오·상태 전이·코드 실행·상호작용·데이터·구조·변경 영향·검증 범위를 구분합니다. 질문에 필요한 관점만 선택합니다 | #17 |
| POL-visualization-02 | 그림마다 대상, 관점, 근거와 범위를 적습니다. 근거는 명세 기준·코드 해석·실행 관측으로 구분하고 가상 예시를 표시합니다 | #17 |
| POL-visualization-03 | 명세의 기대 동작과 현재 구현·관측 결과가 다르면 차이를 보고합니다. 코드나 그림으로 합의되지 않은 동작을 확정하지 않습니다 | #17 |
| POL-visualization-04 | 새로 작성·변경하는 UI 기능에 여러 상태와 상태별 표시·조작 차이가 있으면 상태표와 상태도를 연결합니다 | #17 |
| POL-visualization-05 | 상태표의 전이·조건·결과를 그림의 화살표 또는 보이는 주석에 대응시킵니다. 담당 유닛과 기능 TC를 연결합니다 | #17 |
| POL-visualization-06 | 표와 문장에 같은 조건·결과를 유지합니다. 함수 계약과 타입 선언은 기존 유닛·타입 명세에 둡니다 | #17 |
| POL-visualization-07 | 정적 관계는 Mermaid로 표현합니다. 검증 범위는 TC·결과·근거 표로 표현할 수 있습니다. 표시 성공은 동작 검증이 아닙니다 | #17 |
| POL-visualization-08 | spec은 그림으로 빠진 결정을 확인합니다. wiki 반영과 구현은 기존 확정·sync 절차를 따릅니다 | #17 |
| POL-visualization-09 | audit은 그림·명세·코드·TC·실행 근거를 대조합니다. 실행하지 않은 동작은 미검증으로 보고하고 대상 파일은 수정하지 않습니다 | #17 |
| POL-visualization-10 | 모든 관점을 일괄 작성하거나 기존 문서 전체에 소급 적용하지 않습니다. 새 문서 종류·필수 frontmatter·서버·런타임 의존성은 추가하지 않습니다 | #17 |
