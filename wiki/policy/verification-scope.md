# 검증 범위

검증 범위는 변경이 영향을 주는 코드·기능·계약과 그 완료 기준을 증명할 검사입니다.
핫픽스는 사용자가 긴급한 버그 수정을 요청한 작업입니다. 파일 수와 중요도는 검증 축소의 근거가 아닙니다.

## 규칙

| ID | 규칙 | 근거 |
| --- | --- | --- |
| POL-verification-01 | hotfix는 진입과 검증 계획을 담당합니다. 이슈·확정·선점·구현·PR·머지는 기존 spec·sync의 권한과 절차를 따릅니다 | #22 |
| POL-verification-02 | 일반 sync는 기존 검증 범위를 유지합니다. 사용자가 핫픽스로 요청한 작업에만 영향 범위 검증을 적용합니다 | #22 |
| POL-verification-03 | 실행 전에 재현 조건, 기대 결과, 변경 대상, 영향 경계, 선택·제외한 검사와 이유, 명령·실행 주체·TC를 기록합니다 | #22 |
| POL-verification-04 | 버그 재현, 변경 유닛의 관련 회귀와 영향받는 기능을 검증합니다. 영향이 이어지면 사용처 한 단계에서 멈추지 않습니다 | #22 |
| POL-verification-05 | 도구의 기존 설정과 검사 의미를 유지합니다. 부분 실행이 불가능한 검사는 그 도구의 전체 명령을 실행합니다 | #22 |
| POL-verification-06 | 전체 확대 조건은 공통 기준의 표를 따릅니다. 확대해도 수정 범위를 넓히지 않고 범위 밖 실패는 기존 중단 규칙으로 처리합니다 | #22 |
| POL-verification-07 | 전체 검증은 저장소가 정한 기존 전체 명령과 필수 CI입니다. 별도 로컬 실행 규칙이 없으면 현재 PR 커밋의 CI 결과를 사용합니다 | #22 |
| POL-verification-08 | 같은 작업의 성공 결과만 재사용합니다. 실행 근거, 충분한 범위와 입력·실행 조건의 동일성이 모두 확인돼야 합니다 | #22 |
| POL-verification-09 | 커밋 해시만으로 동일성을 판단하지 않습니다. 미커밋·추적하지 않은 입력, 관련 설정·의존성·테스트 자료와 외부 상태도 확인합니다 | #22 |
| POL-verification-10 | 내용이 같은 스테이징·커밋이나 무관한 문서 변경은 코드 테스트를 무효화하지 않습니다. 실제 입력이 바뀐 검사만 다시 실행합니다 | #22 |
| POL-verification-11 | sync는 검증 기록을 audit에 넘깁니다. audit은 유효한 결과를 재사용하고 같은 명령을 추가 실행하지 않습니다. 의미 대조는 계속 수행합니다 | #22 |
| POL-verification-12 | 실패·중단·진행 중·미실행·근거 없는 자기 보고는 성공 결과가 아닙니다. 근거가 부족하면 재실행하거나 미검증과 완료 불가 사유를 남깁니다 | #22 |
| POL-verification-13 | 확대 시 기록이 증명하지 못하는 대상을 추가 검증합니다. 도구가 분리를 지원하지 않으면 전체 명령을 다시 실행하고 이유를 적습니다 | #22 |
| POL-verification-14 | 직접 실행·재사용·대기·미검증을 구분하고 명령·범위·TC·입력 식별·환경·종료 코드·근거를 남깁니다. 민감정보 원문은 공개하지 않습니다 | #22 |
| POL-verification-15 | 로컬 재사용은 현재 PR 커밋의 필수 CI를 대신하지 않습니다. 핫픽스 전용 우회, no-spec 예외와 새로운 승인 단계를 추가하지 않습니다 | #22 |

공통 기준과 검증 기록의 형식은 [검증 계획과 실행 근거](../../plugins/bab/skills/sync/references/verification.md)에 있습니다.
