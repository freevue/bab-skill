# 핫픽스 검증

사용자는 `bab:hotfix`로 긴급한 버그 수정을 요청합니다. 에이전트는 영향 범위를 정하고 같은 실행 근거를 sync와 audit에서 공유합니다.

## 구성 유닛

실행 함수 유닛은 없습니다. 기존 도구와 다음 스킬의 문서 절차로 수행합니다.

| 구성 스킬 | 역할 |
| --- | --- |
| [hotfix](../../plugins/bab/skills/hotfix/SKILL.md) | 재현·기대 동작과 검증 계획을 정하고 기존 절차에 전달 |
| [spec](../../plugins/bab/skills/spec/SKILL.md) | 승인된 이슈 등록·확정과 결정 이력 |
| [sync](../../plugins/bab/skills/sync/SKILL.md) | 계획에 따른 구현·실행과 검증 기록 전달 |
| [audit](../../plugins/bab/skills/audit/SKILL.md) | 범위·입력·실행 근거를 대조하고 유효한 결과 재사용 |

## 흐름

1. hotfix는 저장소와 이슈를 확인합니다. 재현 조건과 기대 동작이 빠졌으면 필요한 결정만 질문합니다.
2. 기존 이슈와 이미 승인한 범위를 재사용합니다. 등록·확정이 필요하면 spec을 따릅니다.
3. 변경 대상에서 사용처·기능·공개 계약을 따라 영향 경계를 정합니다.
4. [공통 검증 기준](../../plugins/bab/skills/sync/references/verification.md)으로 선택·제외한 검사, 명령·실행 주체와 확대 이유를 기록합니다.
5. sync가 선점·이슈 게이트·wiki·재현 테스트·구현을 기존 순서로 수행합니다. 핫픽스 계획에 따라 검증합니다.
6. 각 검사에 실제 입력 상태와 환경, 실행 명령·종료 코드·근거를 기록합니다.
7. audit은 기록의 유효성을 판단합니다. 유효하면 재사용하고 의미 대조를 수행합니다. 부족하면 해당 검사를 수행하거나 미검증으로 보고합니다.
8. 입력이 바뀌면 영향을 받는 검사를 다시 수행합니다. 외부 상태가 불명확한 실행 결과는 현재 동작의 근거로 재사용하지 않습니다.
9. 기존 CI가 담당하는 전체 검증은 현재 PR 커밋의 결과로 확인합니다. 대기·실패를 로컬 결과로 통과 처리하지 않습니다.
10. PR에 직접 실행·재사용·대기·미검증을 구분하고, 범위 밖 실패는 기존 sync의 중단 기준을 따릅니다.

### 전체 검증 확대

공통 기준의 표는 저장소·사용자 지시, 공개 계약, 공통 경로, 데이터·권한 규칙, 실행 기반, 경계 불명확과 예상 밖 실패를 구분합니다.
검증 확대와 수정 범위 확대는 별개입니다. 검사를 분리할 수 없다면 해당 도구의 기존 전체 명령을 사용합니다.

### 검증 기록

기록은 같은 작업에서 확인 가능한 문서·대화·PR의 검증 표로 전달합니다. 영구 캐시나 새 실행기를 만들지 않습니다.
코드·테스트·자료·설정·의존성의 내용과 명령·작업 경로·도구·환경이 같아야 재사용합니다.
기록의 실제 실행 범위가 요청 범위를 포함해야 합니다. 명세와 코드의 의미를 읽는 판단은 실행 결과로 대체하지 않습니다.
