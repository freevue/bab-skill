# 한글 작성 규칙

이 규칙은 [simple-english](../../simple-english/SKILL.md)의 문서 규칙을 한글에 맞게 옮긴 것입니다. 한 번 읽고 뜻을 이해할 수 있도록 씁니다. 영어 전용 규칙인 승인 어휘, 시제, 관사와 철자는 적용하지 않습니다.

아래 규칙은 문서 본문에 적용합니다. 사용자에게 보고할 때는 [공통 브리핑 규칙](../../setup/assets/claude-section.md#최종-브리핑)을 따릅니다. 이슈·PR·wiki 템플릿의 제목과 표는 문서 구조이므로 유지합니다.

## 규칙

| 번호 | 규칙 | 예 |
| --- | --- | --- |
| 1 | 코드, 식별자, 명령, 경로, 오류 문구, 제품 이름, 사실은 바꾸지 않습니다 | `drift-check.mjs`, `status:decided`는 그대로 둡니다 |
| 2 | 한 문장에 한 지시나 사실만 적습니다. 절차 문장은 20어절, 설명 문장은 25어절 이하로 씁니다. 문단은 한 주제로 6문장 이하로 씁니다 | 긴 문장은 둘로 나눕니다 |
| 3 | 조사와 주어를 생략한 전보체를 쓰지 않습니다 | "파일 확인 후 실행" 대신 "파일이 있는지 확인한 뒤 실행합니다" |
| 4 | 조건을 명령 앞에 씁니다 | "빌드가 실패하면, 로그를 읽습니다" |
| 5 | 누가 하는지 씁니다. 행위자는 사람, 에이전트, CI 중 하나입니다 | "CI가 라벨을 뗍니다" |
| 6 | 모호한 표현을 쓰지 않습니다. 필수는 "~합니다", 가능은 "~할 수 있습니다"로 씁니다. 추측은 `추측`이라고 표시합니다 | `~할 수도 있습니다`, `~일 것입니다`, `~하는 것이 좋습니다`를 쓰지 않습니다 |
| 7 | 문장을 잇는 데 `;`, `—`, `–`를 쓰지 않습니다. 두 문장으로 나누거나 관계를 말로 씁니다 | 범위(`P0~P3`)와 명령 옵션(`--force`)은 예외입니다 |
| 8 | 한 단어는 한 뜻으로만 씁니다. 아래 용어표를 따릅니다 | |
| 9 | 용어는 처음 쓸 때 짧게 정의합니다. 제품 이름과 표준 이름은 정의하지 않습니다 | "드리프트(wiki와 코드가 어긋난 상태)" |
| 10 | 사실을 담지 않는 수식어를 지웁니다 | `단순히`, `효과적으로`, `강력한`, `매우`, `다양한`, `핵심적인` |
| 11 | 서식은 구조를 나타낼 때만 씁니다. 굵게를 강조로 쓰지 않고, 이모지를 쓰지 않습니다. 표는 값을 대조할 때, 목록은 나란한 항목이나 절차를 나타낼 때 씁니다 | 템플릿의 표는 행이 적어도 유지합니다 |
| 12 | 경고는 명령이나 조건을 먼저 쓰고, 위험을 다음에 씁니다 | "운영 DB에 실행하지 않습니다. 행이 지워집니다" |

## 용어표

| 용어 | 뜻 | 쓰지 않는 말 |
| --- | --- | --- |
| 스펙 | 이슈에 기록한 도메인 변경의 합의와 이력 | 요구사항, 티켓 |
| 명세 | wiki에 쓴 현재 개발 형상의 기준 | 문서화, 설명서 |
| 형상 | 명세와 로컬 룰이 정하는 이름, 타입, 동작, 분기 순서와 유닛 관계 | 모양새 |
| 일치 / 불일치 | 명세와 코드의 형상이 같음 / 다름 | 동기화됨, 맞음 |
| 드리프트 | 명세와 코드가 어긋난 상태 | 차이, 괴리 |
| 검사 | 스크립트나 CI가 규칙대로 판정하는 일 | 체크, 점검 |
| 확인 | 사람이나 에이전트가 읽고 판단하는 일 | 체크, 검토 |
| 검증 | 결과가 완료 기준을 충족하는지 근거로 판단하는 일. 동작은 실행 결과로 확인합니다 | 테스트해 봄 |
| 승인 | 사람이 게이트에서 받아들이는 일 | 허가 |
| 확정 | 이슈를 작업 대상으로 정하는 일. 사람이나 에이전트가 하고, 근거를 코멘트로 남깁니다 | 결정 |
| 완결성 | 이슈나 기존 코드를 열지 않고 형상을 재현할 만큼 명세가 갖춰진 상태 | 완성도 |
| 머지 | PR을 기본 브랜치에 합치는 일. bab은 방법과 주체를 정하지 않습니다 | 반영, 병합 |
| 설정 | 동작을 바꾸는 값이나 파일 | 구성, 옵션, 세팅 |
| 구성 | 기능이 어떤 유닛으로 이루어지는지 | 조합, 설정 |

## 기계 검사

스크립트는 일부 모호한 표현과 수식어, 대시, 세미콜론, 굵게, 이모지와 25어절을 넘는 문장을 찾습니다. 절차 문장의 20어절 제한과 문단 길이는 직접 확인합니다.

```bash
node <플러그인 루트>/skills/audit/scripts/prose-check.mjs <파일...>
```

나머지 규칙은 사람이나 에이전트가 읽고 확인합니다. 어절 수는 띄어쓰기로 세므로 실제 읽기 난이도와 다를 수 있습니다. 결과는 신호로 쓰고, 문장을 기계적으로 자르지 않습니다.
