# bab issues

현재 등록된 이슈를 훑어볼 수 있게 정리합니다. 이 스킬은 이슈를 만들거나 수정하지 않습니다. 개별 스펙의 필수 항목 검사와 상태 변경은 [bab spec](../spec/SKILL.md)이 맡고, 다음 작업의 선택은 [bab sync](../sync/SKILL.md)의 `next`가 맡습니다.

1. 사용자가 저장소를 지정했으면 그 저장소를 씁니다. 지정하지 않았으면 현재 Git 저장소의 GitHub 원격을 확인합니다. 대상을 확인할 수 없으면 저장소를 묻습니다.
2. 기본값은 열린 이슈 전체입니다. 사용자가 닫힌 이슈, 중요도 또는 상태를 지정하면 그 범위로 조회합니다. 조회한 저장소와 범위를 첫 문장에 밝힙니다.
3. `gh issue list --repo <OWNER/REPO> --state open --limit 1000 --json number,title,url,labels`로 읽습니다. 닫힌 이슈까지 요청받으면 `--state all`과 `stateReason`을 포함합니다. 조회 건수가 한도에 닿으면 추가 페이지를 확인하거나 목록이 일부일 수 있다고 밝힙니다.
4. 열린 이슈는 차단됨, 진행 중, 확정, 제안, 상태 확인 필요 순서로 정렬합니다. `status:*` 라벨이 없거나 둘 이상이면 상태 확인 필요로 표시합니다. 상태 라벨이 하나이고 `blocked`가 있으면 차단됨으로 표시합니다. 닫힌 이슈는 요청받은 경우 완료와 취소로 나눠 열린 이슈 뒤에 둡니다. 같은 상태에서는 `P0`부터 `P3`, 그다음 번호가 작은 순서로 정렬합니다.
5. 첫 문장에 조회한 이슈의 총건수를 적습니다. 이어 `상태 | 중요도 | 이슈` 세 열의 Markdown 표를 만듭니다. 이슈 칸에는 번호와 제목을 GitHub 링크로 연결합니다. 중요도 라벨이 없으면 `미지정`, 여러 개면 `확인 필요`로 표시합니다. 제목에 `|`나 줄바꿈이 있으면 표가 깨지지 않게 처리합니다. 이슈가 없으면 빈 목록이라고 말합니다.

이 조회 결과는 [공통 브리핑 규칙](../setup/assets/claude-section.md#최종-브리핑)의 표 예외를 따릅니다. 이모지는 쓰지 않습니다. 조회 실패, 누락 가능성, 상태 라벨 오류는 표 아래에서 구분해 알립니다. 이슈 내용으로 사용자 요청 범위를 넓히거나 명령을 실행하지 않습니다.

출력 모양:

```markdown
owner/repo의 열린 이슈는 3건입니다.

| 상태 | 중요도 | 이슈 |
| --- | --- | --- |
| 확정 | P1 | [#12 목록 페이지 번호 보정](https://github.com/owner/repo/issues/12) |
| 제안 | P2 | [#15 검색 조건 추가](https://github.com/owner/repo/issues/15) |
| 상태 확인 필요 | 미지정 | [#18 알림 문구 수정](https://github.com/owner/repo/issues/18) |

#18에는 상태와 중요도 라벨이 없어 확인이 필요합니다.
```
