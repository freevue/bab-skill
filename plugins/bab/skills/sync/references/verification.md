# 검증 계획과 실행 근거

hotfix는 진입과 계획을, sync는 구현·검사 실행을, audit은 근거·명세·코드의 대조를 담당합니다.
일반 sync의 검증 범위는 유지합니다. 아래 영향 범위 선택은 사용자가 핫픽스로 요청한 작업에 적용합니다.
실행 근거 재사용 기준은 일반 sync와 audit에서도 같습니다. 스킬 이름이 바뀌었다는 이유로 같은 검사를 반복하지 않습니다.

## 핫픽스 검증 계획

검증 범위는 변경이 영향을 주는 코드·기능·계약과 그 완료 기준을 증명할 검사입니다.
검사 전에 아래 내용을 이슈의 작업 기록, 로컬 작업 문서 또는 PR에 적습니다. 기존 기록이 있으면 이어서 씁니다.

| 항목 | 기록할 내용 |
| --- | --- |
| 모드와 대상 | 핫픽스 요청의 근거, 저장소, 이슈, 비교 기준 커밋, 재현 조건과 기대 결과 |
| 영향 경계 | 변경 코드·명세에서 사용하는 쪽으로 이어지는 경로와, 영향이 멈춘다고 판단한 근거 |
| 선택 | 버그 재현, 관련 경계·실패 회귀와 영향받는 기능의 TC, 린트·타입·형상 검사 |
| 실행 | 저장소가 제공하는 실제 명령, 작업 경로와 실행 주체(로컬 또는 기존 CI) |
| 제외 | 제외한 검사와 이번 완료 기준에 필요하지 않은 이유 |
| 확대 | 아래 표의 해당 조건, 전체 검증의 실행 주체와 대기 중인 항목 |

변경한 줄 수나 P0·P1 라벨만으로 범위를 줄이지 않습니다.
코드의 참조와 wiki의 구성 유닛·사용처, 테스트 설정을 함께 확인합니다.
사용처를 넘어 동작 영향이 이어지면 한 단계에서 멈추지 않습니다. 공개 계약이나 관찰 동작이 유지되는 경계까지 따라갑니다.
경계가 확인된 국소 수정은 재현, 관련 유닛 회귀와 영향 기능을 검증합니다. 관계없는 화면·브라우저·UI 상태를 일괄 요구하지 않습니다.
기대 동작이 불명확하면 필요한 결정만 질문합니다. 이미 승인한 내용과 범위는 다시 묻지 않습니다.

검사 명령은 대상 저장소의 도구와 설정을 따릅니다. 부분 실행을 위해 타입·린트·테스트 설정을 우회하지 않습니다.
부분 실행이 불가능한 도구는 해당 검사의 기존 전체 명령을 씁니다. 다른 검사의 범위는 별도로 판단합니다.
테스트 도구가 없으면 기존 sync의 수동 TC 실행을 사용하고 근거가 없으면 미검증으로 남깁니다.

## 전체 검증 확대

전체 검증은 저장소가 정한 기존 전체 검사와 필수 CI입니다. 새 검사 종류를 모두 추가한다는 뜻이 아닙니다.
다음 중 하나라도 해당하면 전체 검증으로 확대하고 이유를 기록합니다.

| 조건 | 판정 |
| --- | --- |
| 규칙·지시 | 저장소·사용자가 전체 검증을 요구하거나 필수 CI가 전체 검증을 수행합니다 |
| 공개 계약 | 공개 함수 시그니처, API 입출력, 여러 기능이 공유하는 타입·이벤트 계약의 동작이 바뀝니다 |
| 공통 경로 | 전역 상태, 공통 미들웨어·프로바이더·캐시·초기화처럼 여러 기능이 쓰는 경로의 동작이 바뀝니다 |
| 데이터·권한 | DB 스키마·마이그레이션·저장 형식, 트랜잭션·무결성, 인증·인가·결제 규칙의 동작이 바뀝니다 |
| 실행 기반 | 런타임 의존성, lock 파일의 의존성 해석 결과, 빌드·컴파일러·테스트 설정이나 환경 조건이 바뀝니다 |
| 경계 불명확 | 사용처·계약 경계를 확인할 수 없거나 필요한 부분 실행 명령이 없습니다 |
| 예상 밖 실패 | 계획으로 설명되지 않는 실패가 발생하거나 실제 변경이 계획의 경계를 벗어납니다 |

부분 실행의 제한이 특정 도구에만 있으면 그 도구만 전체로 확대합니다. 다른 검사의 범위는 별도로 판단합니다.
동작 영향의 경계를 확인할 수 없으면 저장소의 전체 검증으로 확대합니다.

기존 CI가 담당하는 전체 검증은 현재 PR 커밋의 성공 결과를 사용합니다.
저장소가 로컬 전체 실행도 요구하지 않는다면 같은 전체 명령을 로컬에서 추가 실행하도록 요구하지 않습니다.
CI가 끝나기 전에는 대기로 기록합니다. 로컬 검증 후 PR을 열어 CI를 기다릴 수 있지만 필수 결과가 없으면 완료가 아닙니다.
범위를 확대해도 수정 범위를 넓히지 않습니다. 범위 밖 실패는 근거를 보고하고 기존 sync의 중단 규칙을 따릅니다.
기존부터 실패한 항목은 기준선 실패로 구분합니다. 실패·미실행을 통과로 기록하지 않습니다.

## 실행 기록

같은 작업에서 검증 기록을 공유합니다. 대화·로컬 문서·PR의 기존 기록을 사용하고 영구 캐시나 새 실행기를 만들지 않습니다.
검사마다 아래 형식으로 남깁니다. 범위·입력 목록이 길면 확인 가능한 별도 기록을 연결합니다.

| 항목 | 기록할 내용 |
| --- | --- |
| 검사 ID·목적 | 작업 안에서 구분할 이름, 완료 기준과 TC, 실제 검사 범위 |
| 명령·주체 | 명령과 인자, 작업 경로, 로컬 또는 CI, 실행 시점 |
| 입력 식별 | 읽는 코드·명세·테스트·자료·설정·의존성의 경로와 내용 식별 근거 |
| 실행 조건 | 도구 버전과 영향을 주는 환경 조건의 동일성 근거, 외부 상태의 고정 여부 |
| 결과 | 완료 상태, 종료 코드와 결과 요약, 읽을 수 있는 실제 로그·실행 기록의 위치 |
| 사용 | 직접 실행, 재사용한 원본 검사 ID와 이유, 또는 대기·미검증과 사유 |

내용 식별에는 파일 해시나 Git blob 등 실제 내용을 구분하는 값을 사용할 수 있습니다.
미커밋 변경과 추적하지 않은 입력도 포함합니다. HEAD나 파일 수정 시각만 같다는 것은 충분하지 않습니다.
도구 자체와 공통 테스트 도우미도 검사 입력입니다. 입력 범위를 모르면 재사용하지 않습니다.
의존성은 실제 설치 상태와 해석 결과가 같은지 확인합니다. lock 파일만으로 설치 상태를 단정하지 않습니다.
환경 변수·비밀값·개인정보 원문은 공개하지 않습니다. 값 대신 동일성을 확인한 근거를 남기고, 확인이 안 되면 재실행합니다.

## 재사용 판단

sync는 기록을 audit에 전달합니다. audit은 명령을 실행하기 전에 다음 조건을 모두 확인합니다.

1. 같은 작업에서 실제로 실행이 끝나 성공한 기록입니다. 종료 코드와 읽을 수 있는 실행 근거가 있습니다.
2. 실행한 범위가 현재 요청한 검사와 완료 기준을 포함합니다.
3. 관련 입력 내용과 명령·인자·작업 경로·도구·환경 조건이 같습니다.
4. 외부 상태에 의존하면 그 상태의 동일성도 확인됩니다. DB·네트워크·현재 화면의 과거 성공만으로 현재 상태를 증명하지 않습니다.

모두 충족하면 원본 검사 ID와 근거를 인용하고 재사용합니다. 동일 명령의 추가 실행은 하지 않습니다.
audit은 명세의 내부 로직, 실제 코드와 완료 기준의 의미 대조를 계속 수행합니다. 실행 기록은 이 판단을 대신하지 않습니다.
실패·중단·진행 중·미실행·읽지 못하는 근거나 통과라는 자기 보고는 성공 결과로 재사용하지 않습니다.
조건이 부족하면 해당 검사를 수행하거나 미검증과 완료 불가 사유를 보고합니다.

입력이나 조건이 바뀌면 영향을 받는 검사만 무효화합니다. 관련 없는 기록까지 모두 버리지 않습니다.
스테이징·커밋만 바뀌고 입력 내용이 같다면 로컬 기록은 유효합니다.
무관한 문서가 바뀌면 코드 테스트는 재사용할 수 있지만, 그 문서를 읽는 문서 검사는 다시 수행합니다.
`drift-check.mjs`는 wiki 전체, 연결한 코드와 검사 도구를 읽습니다. 일부 파일만 비교해 전체 형상 검사 기록을 재사용하지 않습니다.
wiki 작성 직후와 구현 후는 입력이 다를 수 있습니다. 이전 단계의 성공을 최종 구현의 성공으로 간주하지 않습니다.

범위가 확대되면 기존 기록에 없는 대상을 추가 검증합니다.
도구가 분리를 지원하지 않거나 전체 명령을 요구하면 전체를 다시 실행하고 이유를 적습니다.
기존 기록이 확대 범위와 같은 입력을 이미 충족하면 재사용할 수 있습니다.
로컬 기록의 재사용은 PR의 현재 커밋에서 필수 CI를 확인하는 절차를 대체하지 않습니다.

## 적용 예시

페이지 보정 함수의 내부 분기 수정은 재현·경계값과 해당 목록 동작을 선택할 수 있습니다. 호출 관계와 공개 계약이 유지된 근거를 적습니다.
같은 작업에서 sync가 실행한 유효한 결과를 audit에 전달하면 audit은 그 명령을 다시 실행하지 않습니다.
그 뒤 테스트 자료를 바꾸면 해당 테스트는 다시 수행합니다. 문장만 바꿔 코드 테스트의 입력이 같다면 문서 검사만 다시 수행합니다.
공유 응답 타입의 계약이 바뀌면 줄 수가 작아도 전체 검증으로 확대합니다.
