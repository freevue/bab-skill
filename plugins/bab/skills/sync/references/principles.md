# 원칙

| 원칙 | 언제 | 규칙 |
| --- | --- | --- |
| **작게 만든다** (laziness-protocol) | 변경 크기를 정할 때, 추상화를 더하고 싶을 때 | 문제를 푸는 가장 작은 변경을 고릅니다. 지울 수 있으면 먼저 지웁니다. 쓰는 곳이 하나인 래퍼와 계층은 만들지 않습니다 |
| **동작을 테스트한다** (test-behavior-not-implementation) | 테스트를 쓰거나 고칠 때 | 사용하는 쪽이 관찰할 수 있는 결과만 검사합니다. 내부만 바뀌면 테스트는 계속 통과해야 합니다. wiki TC가 곧 테스트 명세입니다 |
| **실제로 확인한다** (prove-it-works) | 완료라고 말하기 전 | 실제 산출물로 확인합니다. 테스트를 실행하고 결과를 읽습니다. "컴파일된다"나 자기 보고는 증거가 아닙니다 |
| **원인을 고친다** (fix-root-causes) | 실패를 고칠 때 | 증상을 처음 잘못된 지점까지 거슬러 올라가 거기서 고칩니다. 가드는 그 상태가 정상일 때만 해결책입니다 |
| **검증 단위로 나눈다** (sequence-verifiable-units) | 여러 단계 작업, 커밋을 나눌 때 | 각 단위가 검증된 상태로 끝나게 나눕니다. 다음 단위 전에 확인합니다. 실패하는 테스트 커밋이 수정 커밋보다 먼저 옵니다 |
| **규칙을 구조로 만든다** (encode-lessons-in-structure) | 같은 지적을 두 번째 할 때 | 문장을 더하지 말고 검사 스크립트, 타입, 테스트로 만듭니다. 만들 수 없으면 보고만 합니다 |
