# bab milestone

사람이 함께 검토할 목표 단위로 기존 스펙을 정리합니다. 이 스킬은 프로젝트의 마일스톤 셋업입니다. 구현을 시작하지 않습니다.
작업 전에 [공통 규약](references/protocol.md)을 읽습니다. 설정과 다른 스킬의 소비 방법은 이 규약을 따릅니다.

## 도입과 기존 스펙 정리

1. `git rev-parse --show-toplevel`과 Git 원격으로 대상 저장소를 확인합니다. 기존 bab 규칙과 wiki 인덱스를 읽습니다.
2. 기존 `.bab/milestones.json`이 있으면 아래 읽기 도구로 검사합니다. 잘못된 설정은 덮어쓰지 않습니다.
3. GitHub의 마일스톤과 열린 이슈를 전체 페이지로 읽습니다. 이슈 API에 섞인 PR은 스펙 후보에서 제외합니다.

```bash
gh api --paginate --slurp 'repos/OWNER/REPO/milestones?state=all&per_page=100'
gh api --paginate --slurp 'repos/OWNER/REPO/issues?state=open&per_page=100'
```

4. 본문, 상태, 중요도와 필요한 의존관계를 확인합니다. 필수 항목 누락은 표시하고 상태를 바꾸지 않습니다.
5. 사람이 결과를 함께 판단할 목표로 묶습니다. 같은 화면·사용 흐름의 기능과 디자인은 함께 검토하도록 정리합니다.
6. 묶음별 목표, 범위, 완료 기준, 검토할 결과와 선행 목표를 적습니다. 제목·포함 이슈·미배정 후보와 현재 목표의 정리안을 보여줍니다.
7. 기존 소속은 기본으로 유지합니다. 재배정을 요청한 이슈만 이동합니다. 닫힌 과거 이슈는 기본 재분류 대상이 아닙니다.
8. 대화로 정해지지 않은 목표와 범위만 질문합니다. 대상과 방향이 이미 승인됐으면 같은 승인을 다시 묻지 않습니다.
9. 기존 목표와 같은 마일스톤은 번호로 재사용합니다. 제목만 같고 목표가 다르면 자동으로 합치지 않습니다.
10. 원격 변경이 승인됐으면 필요한 마일스톤과 설명을 반영하고 이슈 소속을 연결합니다. 상태·중요도·이슈 본문은 유지합니다.

```bash
gh api --method POST repos/OWNER/REPO/milestones --input <마일스톤 JSON 파일>
gh api --method PATCH repos/OWNER/REPO/milestones/NUMBER --input <설명 JSON 파일>
gh api --method PATCH repos/OWNER/REPO/issues/ISSUE --input <소속 JSON 파일>
```

생성 JSON에는 title과 description을 적습니다. 소속 JSON에는 정수 milestone만 적습니다.
쓰기 직전에 현재 소속을 다시 읽습니다. 정리안을 만든 뒤 소속이 바뀌었으면 덮어쓰지 않고 차이를 보고합니다.

11. 원격 결과를 다시 읽어 생성·소속을 확인합니다. 일부 적용이 실패하면 성공·실패 범위를 보고하고 활성화를 완료로 처리하지 않습니다.
12. 승인된 현재 마일스톤을 설정에 기록합니다. 아직 고르지 않았다면 current를 null로 둡니다. 기존 추가 필드는 보존합니다.
13. 일반 `.bab` 폴더와 일반 설정 파일만 씁니다. 심볼릭 링크는 거부합니다. 임시 루트의 설정을 읽기 도구로 검사한 뒤 반영합니다.
14. 실제 저장 결과를 다시 검사합니다. 원격 변경이 승인되지 않았으면 정리안과 설정 초안만 제공하고 활성화하지 않습니다.

```bash
GH_REPO=OWNER/REPO node <이 스킬 폴더>/scripts/read-milestones.mjs <저장소 루트>
```

재실행 때는 기존 마일스톤·소속·추가 필드를 읽고 필요한 차이만 반영합니다. 같은 결과이면 다시 쓰지 않습니다.
설정은 소속의 복사본을 보관하지 않습니다. 실제 소속은 GitHub에서 확인합니다.

## 현재 목표 변경과 검토

- 사용자가 현재 목표 변경을 요청하면 대상 목표와 열린 상태를 확인하고 current만 바꿉니다.
- 열린 항목이 없어도 완료로 단정하지 않습니다. 목표·완료 기준과 실제 결과를 대조합니다.
- 디자인이 포함됐으면 실제 화면과 사용 흐름의 검토 근거를 확인합니다. 실행 근거가 없으면 미검증으로 남깁니다.
- 종료와 다음 선택은 사용자 지시를 따릅니다. 다음 마일스톤으로 자동 이동하지 않습니다.
- 구현, 스펙 확정, 커밋·푸시·PR·머지·배포·플러그인 설치는 이 셋업에 포함하지 않습니다.
