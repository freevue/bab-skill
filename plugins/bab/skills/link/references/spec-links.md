# spec의 외부 계약·이슈 연결

`.bab/links.json`이 있거나 사용자가 외부 repo를 지정했을 때 적용합니다. 파일이 없으면 기존 단일 repo 절차를 유지합니다.
새 연결이 필요하면 [link](../SKILL.md)의 연결 추가·갱신 절차를 사용합니다. 연결 규약과 표는 [공통 규약](protocol.md)을 따릅니다.

## 필요한 계약 선택

1. 연결 목록의 담당 영역과 계약 설명으로 이번 변경의 후보를 좁힙니다. 등록된 모든 repo의 본문을 읽지 않습니다.
2. 선택한 계약만 읽기 도구로 확인합니다. 미등록 repo는 연결 범위가 정해지기 전까지 자동 탐색하지 않습니다.
3. 기존 계약으로 기대 동작을 충족하면 계약과 기준 커밋만 참조합니다. 외부 이슈를 새로 만들지 않습니다.
4. 계약 변경이 필요하면 어떤 입력·출력·오류·제약이 달라져야 하는지 정리합니다. 상대 repo의 내부 설계는 확정하지 않습니다.
5. 공개 계약이나 담당 영역이 없어서 판단할 수 없으면 미확정으로 보고합니다. 필요한 결정만 사용자와 정리합니다.

## 외부 변경 요청

원본 이슈 번호가 없으면 초안과 연결 계획만 준비합니다. 원본 등록 후 실제 `owner/repo#번호`로 아래 절차를 진행합니다.

1. 대상 repo에서 원본 이슈 식별자와 계약 id로 기존 이슈를 검색합니다. 제목 검색 후보는 본문과 계약 범위를 확인합니다.
2. 기존 이슈가 있으면 그 이슈와 관계를 재사용합니다. 취소·종료 이슈는 완료 내용과 현재 요구가 같은지 확인합니다.
3. 없으면 spec 필수 항목으로 제안 초안을 만듭니다. Wiki에는 대상 repo의 기존 또는 예정 wiki 경로를 넣습니다.
4. 요청 내용, 필요한 계약 변화와 완료 기준을 기록합니다. 상대 repo의 정확한 함수·타입 설계는 그 repo에서 구체화합니다.
5. 생성 직전에 같은 원본·대상·계약 식별자로 다시 검색합니다. 사용자에게 승인된 대상 repo와 쓰기 권한을 확인합니다.
6. 외부 등록까지 승인됐으면 제안 상태로 등록합니다. 상태를 확정하거나 구현을 시작하는 권한으로 넓히지 않습니다.
7. 외부 등록이 승인되지 않았으면 완성한 초안과 연결 계획을 제공합니다. 원격 이슈와 라벨을 바꾸지 않습니다.
8. 원본 이슈의 Links에 depends-on 또는 related를 기록합니다. 원본 수정 권한이 없으면 변경 초안을 제공합니다.
9. 생성한 상대 이슈에는 원본 링크와 중복 검색 식별자를 남깁니다. 같은 요청을 다시 원본으로 전파하지 않습니다.

이슈 등록과 수정에는 확인한 `--repo OWNER/REPO`를 사용합니다. 조회 실패를 기존 이슈가 없다는 뜻으로 처리하지 않습니다.
다중 repo 등록 도중 실패하면 생성된 이슈 번호와 남은 작업을 기록합니다. 재실행 시 이미 생성된 이슈를 재사용합니다.
동일한 요청의 동시 등록을 예약하는 원격 잠금은 제공하지 않습니다. 기존 조회만으로 동시 중복 방지를 보장하지 않습니다.

## wiki·sync에서 소비

wiki는 내부 issues와 외부 연결 표를 구분합니다. 작업에 필요한 계약 원문은 제공 repo의 지정한 섹션에서 읽습니다.
sync 시작 시 기록한 기준 커밋과 현재 선택 섹션을 비교합니다. 관련 계약 내용이 같으면 기존 기준을 유지할 수 있습니다.
계약이 바뀌었으면 영향과 스펙 재확정 필요 여부를 확인합니다. 바뀐 계약을 자동 승인하거나 외부 이슈를 진행하지 않습니다.
의존 조건이 계약 확정인지 구현·배포·통합 검증인지 확인합니다. 충족하지 못한 조건은 미확정 또는 미검증으로 보고합니다.
